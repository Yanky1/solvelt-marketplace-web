## Theming
Tokens are CSS custom properties in `app/styles/tokens.css` (from the Solvelt portal). Dark values apply under `@media (prefers-color-scheme: dark)` for `:root:not([data-theme='light'])` and for `:root[data-theme='dark']`. Bright images use `filter: brightness(var(--img-dim))`.

## Components (slice 1)
`app/components/ui`: Button, LinkButton, Input/Field (label, hint, error), Select, Checkbox, Card, Badge, Price, RatingStars, Skeleton, EmptyState, Breadcrumb, Pagination, Modal/Drawer, Toast. Shell: Logo, Header (search, nav, account, cart placeholder, mobile drawer), Footer (theme switch), skip link, error/404 pages. `/styleguide` (noindex) shows them all and is covered by axe in light and dark.

| W1-13 | 2026-11-04 | All API calls go through `apiFetch` (`app/lib/api.server.ts`). It sets the client IP header from the socket peer; `X-Forwarded-For` is honoured only when the peer matches `TRUSTED_PROXIES` (IPs or IPv4 CIDRs, comma separated), walking the chain right to left past trusted hops, ignoring malformed chains. A client-supplied copy of the header is never forwarded. (Header details superseded by W1-14.) Express `trust proxy` is off. | Orchestrator addition to brief item 4: the API rate-limits per end-user IP but all traffic arrives from this server. |
| W1-14 | 2026-11-04 | Forwarding contract is final (API repo `docs/API.md`, API main 3b48083). `apiFetch` sends on every call, and only when an IP could be resolved: `X-Solvelt-Client-Ip`, `X-Solvelt-Client-Timestamp` (unix seconds, floored, our clock) and `X-Solvelt-Client-Signature` = `v1=` + lower-hex HMAC-SHA256(`WEB_FORWARDING_KEY`, `"<timestamp>\n<ip>"`). The key is env `WEB_FORWARDING_KEY`; production start-up fails if it is missing, shorter than 32, the dev default, or equal to `SESSION_COOKIE_SECRET`. Test vector: key `dev-only-web-forwarding-key-not-for-production`, ts `1700000000`, ip `203.0.113.9` -> `v1=eaf9dade01862226a6cb91574596e068996969fe53eb32f05d4ec102df81a4e8`. | Orchestrator relay of M1 contract; verified against the API docs. |

## Review 1 (orchestrator review of 9dfb046)
| Id | Date | Decision | Why |

| W1-15 | 2026-11-04 | `safeNext` rejects any control char, whitespace (incl. NBSP) or backslash anywhere, then resolves the value against a dummy origin and returns `pathname+search+hash`, rejecting a result starting with `//`. Rejects tested: tab, newline, space, NUL, NBSP, `https:`, `//`, backslash. | Browsers strip tabs/newlines and read `\` as `/`: `"/\t/evil.example"` became `//evil.example` (HIGH). |
| W1-16 | 2026-11-04 | Anything but `NODE_ENV=development\|test` is production (unset included). In production both secrets must be >= 32 chars, not placeholders (`change-me`, `dev-only`, `example`, ...) and have >= 12 distinct characters. The http exception for `PUBLIC_ORIGIN` is decided on the parsed hostname (`localhost`, `127.0.0.1`), not a regex over the string. E2E/screenshot secrets are random-looking. | Weak or placeholder secrets and `http://localhost.evil.com` were accepted. |
| W1-17 | 2026-11-04 | Security headers are set once in Express middleware in `server.js` for every response: nonce-based CSP (`script-src 'self' 'nonce-…'`, `style-src 'self'` plus `style-src-attr 'unsafe-inline'` because React emits `style=""` attributes, `frame-ancestors 'none'`, `object-src 'none'`, `base-uri`/`form-action 'self'`), nosniff, X-Frame-Options, Referrer-Policy, Permissions-Policy (payment and passkeys allowed for self), COOP, HSTS when `PUBLIC_ORIGIN` is https. The nonce reaches RR through the load context and a `NonceContext`. `entry.server.tsx` sets `Cache-Control: private, no-cache` on HTML unless a route sets its own and `Vary: Cookie`; `handleDataRequest` does the same for `.data` responses. | Hotspot: personalised SSR data must never be shared-cached; HTML had no CSP. |
| W1-18 | 2026-11-04 | Light-mode hero focus ring is `--gold-2`; inputs' placeholder uses `--muted` with opacity 1. | `--ring` on the green hero was 1.6-2.6:1; the browser placeholder grey fails contrast on dark surfaces (axe does not check it). |
| W1-19 | 2026-11-04 | `robots.txt` no longer disallows `/img/` or `/styleguide` (noindex does that job). RR packages are pinned exactly (no `^`). Render abort timer is cleared. Playwright `retries: 0`. | Review items 6 and 7. |
| W1-20 | 2026-11-04 | New E2E checks: computed dark/light body background in every axe case; OS dark/light with no cookie; explicit light beats OS dark; placeholder colour; hero focus colour; noindex meta on 404; security/caching headers on HTML, `.data`, resource routes; nonce differs per request; hydration with no console errors or CSP violations; start-up failures. ## Auth slice A (session, CSRF, sign-up/in/out, verify, forgot/reset)
| Id | Date | Decision | Why |
|---|---|---|---|
| W1-21 | 2026-11-04 | **Assumed API auth contract** (the API's `docs/API.md` lists no auth endpoints yet; the mock in `e2e/mock-api.mjs` implements exactly this; **M1 to confirm or correct**). All JSON. `POST /api/v1/auth/sign-up {email,password,displayName}` -> `204` (same answer for an existing address) or `422 {code:"validation_failed", errors:{field:msg}}`. `POST /api/v1/auth/verify-email {token}` -> `204` or `400 invalid_token`. `POST /api/v1/auth/sign-in {email,password}` -> `200 {token, user:{id,displayName}}`, `401 invalid_credentials`, `403 email_not_verified`, `429`. `POST /api/v1/auth/sign-out` and `/sign-out-all` (Bearer) -> `204`. `POST /api/v1/auth/resend-verification {email}` -> `204` always (enumeration-safe; `429` rate limited; sends a fresh link and invalidates older ones). `POST /api/v1/auth/forgot-password {email}` -> `204` always. `POST /api/v1/auth/reset-password {token,password}` -> `204` or `400 invalid_token`; it also revokes every session. `GET /api/v1/account/me` (Bearer) -> `200 {id,displayName,email}` or `401`. Errors are `{code,message}` as in API.md. | Contract is not published yet; the typed client is in one file (`api-client.server.ts`) so a correction is a small diff. |
| W1-22 | 2026-11-04 | The browser holds one cookie (`solvelt_session`, `__Host-solvelt_session` on https): `HttpOnly; SameSite=Lax; Path=/; Secure` (https), AES-256-GCM sealed with a key derived (HKDF) from `SESSION_COOKIE_SECRET`. Inside: random session id `sid`, issued-at (30 day max) and, after sign-in, the API token. The token is never in HTML, `.data`, JS-readable cookies or storage (E2E asserts all of these), and not even in clear text inside the cookie. | Brief and O-02. |
| W1-23 | 2026-11-04 | CSRF: every action calls `assertCsrf` = Origin check (`assertSameOrigin`) **plus** a per-session token `HMAC(HKDF(secret,"csrf"), "csrf\|"+sid)` from a hidden `csrf` field (`CsrfField`, value from the root loader). Covers sign-in, sign-up, sign-out, verify, forgot, reset and `/theme` (the footer theme form carries a token too). React Router adds its own Origin check (400) in front. Every document gets a visitor session cookie from the root loader when none exists, so anonymous forms have a token. | Brief hotspot "CSRF on every action". Cost: every first visit sets a functional cookie, so HTML cannot be shared-cached (it already varies on Cookie). |
| W1-24 | 2026-11-04 | The session id is **rotated** on sign-in and on sign-out (new `sid`, so earlier CSRF tokens die; the token is dropped on sign-out). A 401 from `/account/me` replaces the cookie with a fresh visitor session. An unreachable API leaves the cookie alone and shows the user as signed out for that request. | Session fixation; expired or revoked sessions must not linger. |
| W1-25 | 2026-11-04 | No account enumeration: sign-up redirects to the same "check your inbox" page whether or not the address exists (no email in the URL); forgot-password always answers the same; sign-in says "Email or password is incorrect." for unknown user and wrong password (only an unverified account is told to verify). Rate limits (429) are shown as "too many attempts". | Standard hardening; the API does the per-account limiting (M1-15). |
| W1-26 | 2026-11-04 | Email verification and password reset links carry a one-time token in the query. The page shows a confirm button and the **POST** consumes it (mail scanners and prefetchers cannot burn it); these routes send `Referrer-Policy: no-referrer` and `Cache-Control: private, no-store`. Nothing logs URLs or bodies. | Tokens in URLs are sensitive. |
| W1-27 | 2026-11-04 | Signed-in pages (`/account`) are `private, no-store`; other HTML is `private, no-cache` with `Vary: Cookie`. Header shows only the first name from the root loader (no email, token or addresses). | Hotspot: never leak one user's data via a shared cache. |
| W1-28 | 2026-11-04 | Browser storage: keys holding user-scoped data must start with `solvelt.user.`. Sign-out (both buttons) clears exactly those keys from localStorage and sessionStorage before submitting; the theme cookie and other keys stay. We store none today; the rule is enforced by a unit and an E2E test for when carts and drafts arrive. | Brief hotspot on storage clearing. |
| W1-29 | 2026-11-04 | Bug found by E2E and fixed: for bot user agents `isbot` selects `onAllReady`, and an extra `onAllReady` handler overwrote it, so HTML hung for crawlers (curl, Googlebot). The abort timer is now cleared on stream close. Test: `headers.spec.ts` "crawlers get complete HTML". | Would have broken SEO. |
| W1-30 | 2026-11-04 | Added `public/favicon.svg` and a `<link rel=icon>`. | An unhandled `/favicon.ico` 404 was a console error. |

## Review 2 (orchestrator review of the client-IP forwarding)
| Id | Date | Decision | Why |
|---|---|---|---|
| W1-31 | 2026-11-04 | `ApiRequestContext.socketAddress` is a required `string`. In development/test `apiFetch` **throws** when it is empty (a route forgot `context.socketAddress`); in production it still sends no `X-Solvelt-Client-*` headers at all and never copies any from the browser request. Tests cover both, including a request carrying forged `X-Solvelt-Client-*` and `X-Forwarded-For` with no socket address. | F1/F6: a missing address silently put all users in one API rate-limit bucket. |
| W1-32 | 2026-11-04 | Client IP parsing (`client-ip.server.ts`) compares addresses as numbers, not strings. Hops may carry `:port`, `[brackets]` and `%zone` (Azure App Gateway, ARR); IPv6 is canonicalised (RFC 5952) and IPv4-mapped IPv6 becomes IPv4; IPv6 proxies and CIDRs are supported. `TRUSTED_PROXIES` is validated strictly at start-up (plain `ip` or `ip/bits`, decimal bits in range, no ports/brackets/zones, IPv4 in dotted form) and fails listing bad entries **by position**. | F2: common proxy formats made resolution fall back to the proxy's own address. |
| W1-33 | 2026-11-04 | Operations: the API is shrinking the forwarding timestamp window from 300 s to 60 s (O-09). The signer uses the server clock, so web servers must keep NTP in sync (drift over ~60 s makes the API ignore the headers and rate-limit us as unsigned traffic). | Orchestrator heads-up. |

| W1-34 | 2026-11-04 | E2E starts a second server with an https `PUBLIC_ORIGIN` and asserts `Strict-Transport-Security` (max-age >= 1 year, includeSubDomains) and the `__Host-` Secure HttpOnly session cookie; removing HSTS from `server.js` fails it. | Orchestrator verification of review-1: HSTS removal previously passed. |

| W1-35 | 2026-11-04 | **Assumed API contract, part 2** (extends W1-21; mock-implemented; M1 to confirm). All need Bearer; another user's resource is `404`. `GET/PUT /api/v1/account/profile` (`{id,displayName,email,phone}`; PUT takes `{displayName,phone}`, `422 {errors}`). `GET/POST /api/v1/account/addresses`, `GET/PUT/DELETE /api/v1/account/addresses/{id}`, `POST .../{id}/default`; address = `{id,fullName,line1,line2,city,region,postalCode,country (ISO-3166 alpha-2),phone,isDefault}`; the first address becomes the default, setting a default unsets the others, deleting the default promotes another. `GET /api/v1/account/passkeys` -> `[{id,name,createdAt,lastUsedAt}]`; `POST .../passkeys/options` -> `{challengeId, options}` (WebAuthn creation options as JSON, base64url fields); `POST .../passkeys {challengeId,name,credential}` -> `201` / `400 invalid_challenge` / `409 already_registered`; `DELETE .../passkeys/{id}`. | W1-38 | 2026-11-04 | Account pages call `requireAccount` (no token -> sign-in with `?next=`) and map API failures with `failAccount`: 401 -> sign-in, 404 (unknown or someone else's id) -> the 404 page, anything else -> 503. | W1-40 | 2026-11-04 | `html { scroll-padding-top: 9rem }` keeps fields clear of the sticky header (axe found a field partly under it on phones), and the checkbox is 24 px (WCAG 2.2 target size).
